Arquitectura de Software

El sistema HuilaTour implementará una arquitectura de tres capas complementada con el patrón de diseño MVC (Modelo–Vista–Controlador).

Descripción General

La arquitectura del sistema tiene como propósito separar las responsabilidades, facilitar el mantenimiento y permitir una evolución organizada de los diferentes componentes de HuilaTour.


La estructura combina una arquitectura de tres capas con el patrón MVC, permitiendo que el sistema sea modular, organizado, escalable y fácil de mantener.

Arquitectura de Tres Capas

Capa de Presentación


Es la encargada de proporcionar la interfaz de interacción con los usuarios del sistema.


Estará desarrollada mediante HTML, CSS y JavaScript. Permitirá la visualización de información turística, interacción con formularios, consulta de destinos, gestión de reservas y demás funcionalidades disponibles para turistas, visitantes, operadores y administradores.

Capa de Negocio


Contiene la lógica y las reglas de funcionamiento de HuilaTour.


Será desarrollada en Java y se encargará de procesar las solicitudes provenientes de la capa de presentación, aplicar las reglas del sistema y coordinar las operaciones necesarias antes de acceder a los datos.

Capa de Datos


Se encarga de la persistencia y recuperación de la información del sistema.


Esta capa será implementada mediante Java para realizar las operaciones de acceso a datos y PostgreSQL como sistema gestor de base de datos.


En ella se gestionan entidades como usuarios, destinos, operadores, reservas, reseñas y demás información requerida por la plataforma.

Patrón de Diseño MVC

De manera complementaria, el patrón MVC permite organizar los componentes de la aplicación en tres elementos principales:


Modelo

Representa los datos y las entidades que maneja el sistema, como usuarios, destinos, operadores, reservas y reseñas.

Vista

Corresponde a las interfaces desarrolladas con HTML y CSS, complementadas con JavaScript para proporcionar interacción dinámica al usuario.

Controlador

Implementado en Java, recibe las solicitudes provenientes de la interfaz, las dirige hacia la lógica de negocio y coordina la respuesta que será presentada al usuario.

Beneficios de la Arquitectura

📌 Separación de responsabilidades

Cada componente del sistema tiene una función específica, facilitando la organización del proyecto.

🔧 Facilidad de mantenimiento

Las modificaciones pueden realizarse sin afectar significativamente las demás partes del sistema.

🧪 Facilidad para realizar pruebas

La separación de componentes permite probar cada parte del sistema de manera más organizada.

📈 Escalabilidad

Permite incorporar nuevas funcionalidades y realizar mejoras en el sistema de manera organizada.


La arquitectura de HuilaTour organiza el sistema en capas y utiliza el patrón MVC (Modelo–Vista–Controlador), separando la presentación, la lógica de negocio y el acceso a los datos.


Esta estructura permite reducir el acoplamiento entre las diferentes partes del sistema, facilitar las pruebas y el mantenimiento, y posibilitar la incorporación o modificación de funcionalidades sin afectar significativamente el resto de la aplicación.
